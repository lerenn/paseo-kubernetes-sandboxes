Getting started

Admin setup

  1. Set up the Gateway and Standard controller from one shared Helm values file. Add a separate Docker controller in an approved namespace if you offer Docker. Prepare shared workspace storage and a persistent volume for Gateway routing.
  2. Use cert-manager for private controller and Gateway client TLS. Provide the Gateway serving certificate and expose its HTTPS endpoint on a route that carries bidirectional HTTP/2.
  3. Give each Paseo daemon one Gateway token and grant Standard and, where appropriate, Docker. Share the HTTPS URL, daemon-local token file path and private Gateway CA path if needed.

Helm values and migration

User setup

  1. If needed, install the plugin on the daemon running Paseo 0.17.5 or later and Node.js 22 or later. 
    paseo plugin install git:lerenn/paseo-kubernetes-sandboxes:plugin --ref v0.6.0
  2. In Kubernetes Sandbox → Gateway, enter the URL, token file path and optional CA file path provided by your administrator. Select Check connection, then Save Gateway.
  3. In Workspaces, select Enable sandbox. Standard is preselected when authorized. Select Docker (privileged) explicitly when the workspace needs Docker and your token grants it.

Enable Require a sandbox profile in Gateway to require an authorized profile on new workspace launches.

Upgrading from direct connections? Wait for your administrator to confirm the Gateway is ready and the old sandboxes are stopped. Upgrade the existing plugin, then select Gateway → Migrate to Gateway to move your saved assignments.
