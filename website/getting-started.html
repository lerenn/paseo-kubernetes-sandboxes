Getting started

Admin setup

On Kubernetes 1.34 or later, deploy the controller with Helm in a dedicated namespace. Configure a sandbox image, shared storage and profiles, and provision a scoped token for each daemon.

Give the user a private HTTPS endpoint reachable over HTTP/2 from the Paseo daemon, the absolute path to the token file on that daemon, and the CA file path if needed. For commands and details on TLS, storage and tokens, see the Reference.

User setup

  1. If needed, install the plugin on the daemon running Paseo 0.17.5 or later and Node.js 22 or later. 
    paseo plugin install git:lerenn/paseo-kubernetes-sandboxes:plugin --ref v0.5.2
  2. In Kubernetes Sandbox, select Add connection. Use standard as the ID for the default connection. Enter the controller URL and absolute file paths as seen by the daemon, including inside its container if applicable. Select Save connection, then Check connection.
  3. Under Workspaces, select Enable sandbox, choose a connection and one of its authorized profiles, then confirm with Enable with profile.

For a lab Docker workspace, ask your administrator for a dedicated Docker controller connection, then add its HTTPS origin, token file and CA file under Controller connections. In Workspaces, select that connection and explicitly choose Docker (privileged). The Standard connection remains the default for new opt-ins.
